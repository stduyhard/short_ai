# AI 短视频 Web 应用设计文档

日期：2026-05-08

## 目标

构建一个云端优先的前后端分离 Web 应用，用户只需输入 `主题` 和 `风格`，系统即可自动生成一条完整的中文竖屏短视频。

面向用户的核心承诺是：

- 自动撰写视频文案
- 自动生成 AI 画面素材
- 自动合成语音解说
- 自动添加背景音乐
- 自动渲染并输出可下载的成片

实现方式采用“多 Agent + 单一编排器”的架构，让产品表面保持一键生成的简洁体验，同时内部具备模块化和可扩展性。

## 产品范围

### V1 范围内

- 中文短视频
- Web 作为产品入口
- 输入字段仅包含 `主题` 和 `风格`
- 从输入到成片的全自动生成流程
- 竖屏视频输出
- 目标时长为 30 到 60 秒
- 以 AI 图片驱动的画面为主，支持运镜、平移、缩放和转场
- 单人中文旁白
- 自动生成并烧录字幕
- 自动匹配背景音乐
- Web 页面内预览和下载最终视频
- 展示分阶段生成进度
- 某一阶段失败后支持按阶段重试

### V1 暂不包含

- 多角色配音
- 真人数字人或口播数字人视频
- 完整时间线编辑器
- 单次任务生成多个版本
- 自动发布到社交平台
- 横屏视频支持
- 长视频项目
- 首次渲染前的精细化手动分镜编辑

## 用户体验

### 主流程

1. 用户打开 Web 应用。
2. 用户输入 `主题`。
3. 用户输入 `风格`。
4. 用户点击 `开始生成`。
5. 系统创建一个生成任务，并跳转到任务详情页。
6. 任务详情页展示整个流水线的生成进度。
7. 各阶段的中间产物会在生成后逐步展示出来。
8. 渲染完成后，用户可以在页面中预览并下载最终视频。

### 输入模型

首版输入界面应刻意保持极简，仅包含：

- `主题`：视频要讲什么
- `风格`：内容调性或创作方向，例如励志、治愈、悬疑、科普、商务感

V1 不向用户暴露时长、比例、音色、供应商、分镜控制等高级参数，这些由系统自动决定。

### 任务详情页

任务详情页应展示 6 个明确可见的阶段：

1. 创意策划
2. 文案生成
3. 分镜生成
4. 视觉素材生成
5. 配音与字幕生成
6. 视频渲染

每个阶段需要展示：

- 状态：待执行、执行中、已完成、失败
- 简短进度说明
- 可用时展示中间产物
- 在可安全重试的情况下提供重试入口

各阶段可展示的中间产物示例：

- 创意策划：创意 brief
- 文案生成：标题和解说文案草稿
- 分镜生成：分镜卡片列表
- 视觉素材生成：生成好的图片或短片段
- 配音生成：音频预览和字幕时间轴
- 视频渲染：最终视频预览

## 系统架构

### 架构风格

V1 采用由中心化编排器控制的多 Agent 流水线。

这不是一个开放式自由协作的 Agent 群聊系统。各 Agent 不直接自由协商，而是由编排器按固定顺序调用，每个 Agent 接收结构化输入并输出结构化结果。

这种设计既保留了“多角色协作”的创作表达，又能避免首版系统出现不必要的不确定性。

### 核心运行组件

- `Frontend App`：负责用户界面、任务创建、进度展示和最终预览
- `Backend API`：负责提供创建任务、查询任务状态、重试阶段、获取产物的接口
- `LangGraph Orchestrator`：负责执行顺序、状态流转、重试策略和产物持久化
- `Agent Modules`：包含 director、script、storyboard、visual、voice、editor 六类 Agent
- `Provider Adapters`：封装外部 LLM、图像、视频、TTS、音乐、存储等服务
- `Render Engine`：负责把画面、解说、字幕、转场、音乐合成为最终 MP4
- `Persistence Layer`：负责存储任务元数据、结构化输出和素材引用

### Agent 角色定义

#### Director Agent

作用：
根据用户输入生成整个视频项目的创意总纲。

职责：

- 决定节奏
- 决定大致时长
- 决定叙事角度
- 决定镜头数量
- 为下游 Agent 定义内容约束

主要输出：

- 创意 brief
- 目标时长范围
- 镜头数量目标
- 风格与节奏指导

#### Script Agent

作用：
撰写完整口播文案和内容表达框架。

职责：

- 生成标题
- 撰写开头钩子
- 撰写完整解说词
- 在适合时生成结尾总结或行动引导

主要输出：

- 视频标题
- 完整解说文案
- 可选的字幕切分或场景映射辅助信息

#### Storyboard Agent

作用：
将文案转换为可用于渲染的场景单元。

职责：

- 把文案拆成多个镜头
- 为每个镜头分配时长
- 定义画面字幕内容
- 描述所需视觉内容和镜头运动意图

主要输出：

- 有序分镜列表
- 每镜头时长
- 视觉描述
- 字幕文案

#### Visual Agent

作用：
为每个分镜生成视觉素材。

职责：

- 将分镜描述转换为适合供应商的提示词
- 调用图片或短视频生成服务
- 校验素材数量与尺寸
- 返回可复用的素材元数据

主要输出：

- 镜头到素材的映射
- 调用供应商时使用的提示词
- 生成出的图片或视频素材 URL / 存储键

#### Voice Agent

作用：
生成旁白音频和字幕时间轴基础信息。

职责：

- 合成中文旁白
- 将字幕文本与最终语音做基础切分
- 提供渲染阶段可继续细化的时间锚点

主要输出：

- 旁白音频文件
- 字幕时间数据
- 音色与语音元数据

#### Editor Agent

作用：
输出最终成片。

职责：

- 按镜头顺序组装素材
- 为静态图片应用平移和缩放等运镜效果
- 添加转场
- 混合旁白和背景音乐
- 将字幕烧录到视频中
- 输出最终 MP4

主要输出：

- 最终渲染视频
- 渲染元数据
- 预览产物

### LangGraph Orchestrator 职责

LangGraph 编排器是整个流水线的运行控制中心。

它负责：

- 校验任务输入
- 创建阶段记录
- 以图节点方式组织并调用各 Agent
- 持久化每一步结构化输出
- 管理失败重试
- 在上游数据无效时阻止下游继续执行
- 更新前端可消费的任务进度模型
- 记录失败原因和重试次数

编排器还应具备未来扩展的基础，以支持：

- 供应商切换
- 局部重生成
- 人工审核节点
- 多版本实验

## 数据流

### 高层流水线

`CreateJob -> DirectorBrief -> ScriptDraft -> StoryboardShots -> VisualAssets -> VoiceTrackAndSubtitles -> FinalRender`

### 阶段契约

每个阶段只读取自己真正需要的上游产物，并写出一个结构化输出对象。外部供应商的原始响应可以为了调试而保存，但下游阶段应只依赖系统内部统一规范化后的数据格式。

这样可以在供应商变化时，尽量降低对整个系统的影响。

### 失败模型

失败必须按阶段隔离。

如果某个阶段失败，应：

- 将该阶段标记为失败
- 保留已完成的上游产物
- 停止执行下游阶段
- 在 UI 中展示错误信息
- 如果该错误可重试，则允许从该阶段重新执行

示例：

- 临时性 API 超时：可重试
- 上游输出结构错误：在上游重新生成前不可重试
- 渲染素材缺失：在素材校验完成后可重试

## 数据模型

系统至少需要存储以下实体。

### Job

- job id
- created at
- updated at
- 用户输入的 topic
- 用户输入的 style
- 当前阶段
- 整体状态
- 最终视频 URL 或存储键
- 预览视频 URL 或存储键

### Stage Run

- 阶段名称
- 状态
- 开始时间
- 完成时间
- 重试次数
- 错误信息
- 结构化输出 payload

### Asset

- asset id
- job id
- 来源阶段
- 素材类型
- 本地路径或远程 URL
- 如适用则记录时长
- 如适用则记录宽高
- 供应商元数据

## 前端设计要求

### 核心页面

- 主题和风格输入页
- 带实时进度的任务详情页
- 带预览和下载能力的结果页

### 前端职责边界

前端只负责用户交互和展示，不承载核心生成逻辑。

前端需要通过独立 API 与后端通信，至少覆盖：

- 创建生成任务
- 查询任务状态和阶段产物
- 发起阶段重试
- 获取最终视频和素材预览地址

前端不直接持有任何模型密钥，也不直接调用云端生成供应商。

### UI 原则

- 整体体验必须保持“一键生成”的简单感
- 进度不能隐藏在单一 loading spinner 后面
- 中间产物应帮助用户建立对生成过程的信任
- 失败场景应让用户感觉可以恢复，而不是彻底中断

### 推荐 UI 状态

- 提交前空状态
- 创建任务后的排队状态
- 按阶段展示的执行中状态
- 后续阶段仍在执行时的部分结果可见状态
- 阶段失败并支持重试的状态
- 已完成且可预览最终视频的状态

## 技术栈建议

### 前端技术栈

- 使用独立前端应用承载输入、进度和结果页面
- 推荐使用 `Next.js` 或 `React + Vite` 构建前端
- 前端通过 HTTP API 与后端服务通信
- 使用 React 构建任务进度展示界面

这样可以保持前端体验灵活，同时不把 AI 编排和媒体处理逻辑耦合进前端运行时。

### 后端技术栈

- 使用 `FastAPI` 作为后端 API 框架
- 使用 `LangGraph` 作为多 Agent 工作流编排核心
- 后端负责 Agent 调用、状态持久化、供应商集成和任务调度
- 需要支持适合长耗时媒体任务的后台任务执行模式

推荐后端按职责拆分为：

- `API 层`：接收前端请求并返回任务状态
- `应用服务层`：处理任务创建、重试、查询、素材访问控制
- `LangGraph 工作流层`：管理 director、script、storyboard、visual、voice、editor 节点流转
- `Provider 层`：封装各类外部 AI 与媒体服务
- `渲染层`：负责最终视频合成

### 存储

系统需要同时具备以下持久化能力：

- 任务记录存储
- 各阶段结构化输出存储
- 生成素材存储
- 最终渲染视频存储

具体使用哪种数据库和对象存储可以放到实现计划阶段决定，但设计上明确要求同时具备元数据存储和二进制素材存储。

### 渲染能力

渲染层至少应支持：

- 图片序列与基础运镜
- 字幕叠加
- 背景音乐混音
- 旁白对齐
- 竖屏 MP4 输出

实现选型应优先考虑服务端稳定渲染，而不是完全依赖浏览器本地合成。

推荐采用：

- `Remotion` 作为模板化视频编排与主渲染层
- `FFmpeg` 作为素材预处理、音频混音、转码和兜底后处理层

这种组合更适合“前端分离 + Python 后端编排 + 服务端自动成片”的产品形态。

## Provider 层要求

Provider 层必须通过稳定的内部接口屏蔽外部服务差异。

V1 至少要支持以下供应商能力类别：

- LLM 文本生成
- 图片生成
- 可选的短视频生成
- TTS 语音合成
- 背景音乐选择或生成
- 资产存储

设计上不应把某一家供应商硬编码进 LangGraph 工作流。供应商专属的提示词格式、密钥配置和响应解析逻辑都应封装在 adapter 层。

## 质量约束

### 功能质量

- 生成结果从开头钩子到结尾应保持内容连贯
- 旁白和字幕的时间对齐应满足常规短视频观看体验
- 视觉素材应与目标风格一致
- 正常情况下最终输出应无需手工剪辑即可观看

### 运行质量

- 长耗时任务必须可见进度
- 失败任务必须保留有价值的中间产物
- 外部供应商失败不能破坏已完成阶段的数据
- 同类任务的重复执行结果必须可追踪

## 安全与配置

应用需要接入多个云端供应商，因此会使用 API Key。所有密钥必须只保留在后端服务端，绝不能暴露给浏览器。

系统应支持基于环境变量的供应商配置，以便后续切换供应商时不需要重构整个流水线。

由于生成素材和调用模型会产生成本，实施时应记录调用日志和供应商追踪信息，即使 V1 不提供完整账单控制界面。

前后端分离后，还应额外考虑：

- 前端到后端的鉴权方式
- 后端对任务访问范围的控制
- 素材预览 URL 的有效期和访问权限

## 测试策略

V1 应至少覆盖以下几类测试。

### 单元测试

- 阶段契约校验
- LangGraph 工作流状态流转
- Provider adapter 规范化逻辑

### 集成测试

- 使用 mocked providers 跑通端到端流水线
- 覆盖失败与重试场景
- 校验渲染阶段输入是否合法
- 覆盖前后端 API 集成场景

### 手工验证

- 同一主题下测试多种风格生成效果
- 同一风格下测试多种主题生成效果
- 验证任务详情页的进度展示行为
- 验证失败阶段的重试体验
- 验证最终视频预览和下载行为

## 实施说明

首个可用版本应优先追求“稳定的一键生成体验”，而不是“最大化用户控制能力”。

一个好的 V1 应具备这些特征：

- 用户可以从极少输入开始
- 系统能稳定产出一条可观看的短视频
- 进度对用户清晰可见
- 某一阶段失败后可以局部重生成

更高级的编辑控制能力，应建立在基础流程稳定可靠之后再逐步增加。

## 延后到实现计划阶段的决策

以下问题会影响具体实施方式，但不影响本设计文档定义的产品边界，因此延后到 implementation planning 阶段处理：

- 具体选择哪种数据库
- 具体选择哪种对象存储
- 每类能力具体接入哪家供应商
- 后台任务机制具体如何实现
- V1 的视觉素材是否只用图片，还是混入短视频片段
- 前端最终使用 `Next.js` 还是 `React + Vite`

渲染技术栈方向在本设计中已收敛为 `Remotion + FFmpeg`，实现阶段只需确定具体目录结构、调用方式和部署方案。

这些属于实现决策，而不是未定义的产品需求。
